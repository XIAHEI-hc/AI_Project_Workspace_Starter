# 通用边界与扩展建议

## 通用核心

项目组合、目标、阶段、里程碑、事项、决策、证据、收益以及它们的 ID 关系。缺少某种材料时可为空，不为满足表单而捏造内容。

## 可选连接

| 来源 | 可用于证明 | 不能单独证明 |
| --- | --- | --- |
| Git 仓库 | 某分支在某时刻的代码和提交 | 用户实际使用了这版、功能被验收 |
| ZIP 交付包 | 存在某个交付物 | 服务器确实运行该包 |
| 测试日志 | 特定版本、条件下的测试结果 | 所有环境都通过、收益已实现 |
| 会议记录 | 某人提出的观点或明确决定 | 未出席者同意、决定已执行 |
| 页面截图 | 截图时页面展示的状态 | 后端行为可靠、长期效果稳定 |
| 指标报表 | 所统计范围内的观察数据 | 变化必然由本项目造成 |

## 后续增强

多用户协作、角色权限、外部提醒、自动轮询仓库、定时报告、附件解析、全文检索、跨项目依赖、变更审批和图表可按实际需要增加。它们应该复用同一项目事实，不能让外部服务与 HTML 各自维护一套状态。

## 页面调整

可修改 `templates/style.css`、`scripts/workspace.py` 的 HTML 函数并重建。页面应当依据问题来分配主题：项目组合看取舍，路线图看顺序，事项看执行，决定页看理由，证据页看验收，收益页看实际变化。新项目无需复制或重写每个 HTML 文件。
