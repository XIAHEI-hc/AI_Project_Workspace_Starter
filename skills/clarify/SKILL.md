# 澄清事项

1. 区分已发生的问题、未来风险、未成形想法、希望达成的需求和具体执行任务。
2. 写清现象、影响对象、证据、希望改变的结果、未知点；不凭“听起来重要”宣布紧急。
3. 与项目目标、里程碑和现有事项建立 ID 关系；重复事项更新原记录并在变更日志标明合并原因。
4. 证据不足保留 `待澄清`；不要把 AI 推断写成用户已经确认的需求。
5. 用户要求排序时继续读 `../plan/SKILL.md`。
