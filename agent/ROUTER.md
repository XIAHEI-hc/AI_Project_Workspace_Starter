# 意图路由

仅加载本次需要的项目内技能。复合请求按“材料 → 分类与关系 → 计划或状态 → 页面”顺序处理，避免多个技能各自维护一份事实。

| 用户意图或材料 | 读取的技能 | 主要产物 |
| --- | --- | --- |
| 突然想到、上传资料、会议记录、语音转写、截图 | `skills/intake/SKILL.md` | 原始材料与待分类事项 |
| 问题、需求、机会、去重、关联、价值理由 | `skills/clarify/SKILL.md` | 事项与问题—目标链 |
| 顺序、优先级、路线图、里程碑、资源冲突 | `skills/plan/SKILL.md` | 阶段安排、依赖和取舍理由 |
| 任务进展、阻塞、风险、周回顾、变更 | `skills/track/SKILL.md` | 状态、风险和决策记录 |
| 测试、交付、部署、验收、收益核对 | `skills/evidence/SKILL.md` | 证据链和待验证结论 |
| 仓库分支、提交、版本或源码分析 | `skills/source/SKILL.md` | 来源版本和提交摘要 |
| 总览、汇报、HTML 页面、导航 | `skills/publish/SKILL.md` | 校验与静态页面 |

用户只是提问时，可只分析并提出建议。用户要求“记下来、更新项目、处理材料”等行动时，执行写入和重建。找不到目标项目且用户意图明确是创建项目时，可运行 `init`；目标含糊时避免把内容写进示例项目。
